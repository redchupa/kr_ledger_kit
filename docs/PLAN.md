# KR Ledger Kit — 개발 계획서

> Home Assistant 안드로이드 컴패니언 앱의 `last_notification` 센서로 들어오는
> 카드·은행·페이 알림을 자동으로 읽어 **날짜별 가계부**로 만드는 공개용 HA 통합(HACS).
>
> 이 문서는 공개 저장소에 올라가므로 실제 이름·계좌·카드번호는 모두 가렸다.

### 분석에서 나온 핵심 설계 이슈

1. **중복 제거가 필수** — 한 번 결제하면 *카드사 문자 + 카드사 앱 + 삼성페이* 최대 3건. 금액 + 거래시각(±3분) + 가맹점 유사도로 하나로 합치고, 정보가 가장 풍부한 쪽(문자)을 대표로 삼는다.
2. **거래시각 ≠ 알림시각** — 롯데 취소 문자는 11/09에 왔지만 거래일은 11/06. 본문 날짜·시각을 우선, 없으면 `post_time` 사용. 연도는 본문에 없으므로 연말·연초 경계 처리 필요.
3. **본인 계좌 간 이체는 지출이 아님** — "본인명 → 사업자통장" 같은 이체는 `transfer`로 분리해야 이중 계산이 안 된다.
4. **계정(지갑) 개념 필요** — 개인카드 / 법인카드 / 개인사업자통장이 섞여 있음. 카드·계좌 끝자리 → 계정 매핑, 계정별 "가계부 포함 여부" 설정.
5. **거래가 아닌 금융 알림** — 결제예정금액, 대출 납입 예정, "내일 넷플릭스 나가는 날" 등은 별도 '예정' 데이터로 (나중에 캘린더 표시용).
6. **해외결제** — `USD 32.63` 같은 외화. 원화 확정 금액은 나중에 오므로 일단 외화 그대로 저장 + 환산 예정 표시.
7. **보존 기간** — HA recorder는 기본 10일. 센서에만 의존하면 데이터가 사라진다 → 통합이 **자체 DB에 즉시 저장**해야 함.
8. **state 255자 제한** — 긴 문자는 state에서 잘림. 항상 `android.bigText` → `android.text` → `android.title` 속성 순서로 읽는다.
9. **같은 알림이 연속으로 오면 state가 안 바뀜** — 트리거는 state가 아니라 `post_time`/`pde_noti_id` 속성 변화로 잡는다.
10. **개인정보** — 지금 센서는 지인 문자 대화까지 HA로 보내고 있다. 컴패니언 앱의 *허용 목록(Allow list)* 설정으로 금융 앱·문자만 받도록 안내 필요.
11. **민감 알림 숨김** — Android 15+는 일부 알림 본문을 `민감한 알림 콘텐츠 숨김`으로 가린다. 인식 불가로 표시하고 사용자 수동 입력 유도.

## 2. "학습"보다 나은 방법

처음 생각한 "데이터를 학습"하는 방식(ML)은 이 문제에 맞지 않는다.

- 한국 카드·은행 알림은 **발신처별로 포맷이 고정**되어 있다 → 발신처별 규칙 파서가 정확도 ~100%, 설명 가능, 테스트 가능.
- ML은 학습 데이터가 수천 건 필요하고, 틀렸을 때 왜 틀렸는지 알 수 없고, 금액 같은 숫자를 틀리면 가계부로서 치명적.

**채택안: 규칙 파서 + 미인식 큐 + (선택) AI 보조**

```
알림 ─► 1) 필터(허용 패키지/발신자) ─► 2) 발신처별 규칙 파서 ─► 성공 ─► 거래
                                              │
                                              └ 실패 ─► 3) 미인식 큐 (UI에서 사용자 확인)
                                                         ├ 사용자가 직접 입력/무시
                                                         ├ (선택) HA AI Task로 추출 제안
                                                         └ "규칙 제보" → 자동 익명화된 GitHub 이슈
```

- 미인식 큐가 곧 "데이터 학습" 역할: 쌓인 실패 사례가 새 규칙이 되고, 규칙마다 테스트 픽스처가 추가된다.
- AI 보조는 사용자가 HA에 AI Task 엔티티를 설정한 경우에만 켜지는 옵션(기본 꺼짐). 외부 전송이 생기므로 명시적 동의 필요.

## 3. 아키텍처

**형태: HACS 커스텀 통합 (`custom_components/kr_ledger`) + 사이드바 패널**

애드온이 아닌 통합으로 하는 이유: HA OS/Container/Core 모두 설치 가능, 센서 이벤트를 직접 구독, HACS로 배포·업데이트가 쉬움.

```
kr_ledger_kit/
├─ custom_components/kr_ledger/
│  ├─ __init__.py          # 셋업, 이벤트 구독, 패널 등록
│  ├─ config_flow.py       # 알림 센서 선택(여러 폰), 본인 이름, 옵션
│  ├─ manifest.json
│  ├─ const.py
│  ├─ store.py             # SQLite (/config/kr_ledger/ledger.db)
│  ├─ dedupe.py            # 중복 병합
│  ├─ sensor.py            # 오늘/이번 달 지출, 미인식 건수 등
│  ├─ services.yaml        # add/update/delete/reparse/export
│  ├─ websocket_api.py     # 패널용 조회 API
│  ├─ parser/              # ★ HA 의존 없는 순수 파이썬
│  │  ├─ models.py         # RawNotification, Transaction
│  │  ├─ normalize.py      # 유니코드 방향문자(⁨⁩) 제거, 금액/날짜 파싱
│  │  ├─ registry.py       # 패키지/발신자 → 파서 라우팅
│  │  └─ issuers/          # lotte.py, hyundai.py, kb.py, hana.py, shinhan.py,
│  │                       # kakaobank.py, toss.py, samsungpay.py ...
│  ├─ frontend/            # 빌드된 패널 JS (Lit)
│  └─ translations/ko.json, en.json
├─ frontend/               # 패널 소스 (TypeScript + Lit + Vite)
├─ tests/
│  ├─ fixtures/            # ★ 합성·익명화 알림만 (실제 데이터 금지)
│  ├─ test_parsers.py
│  ├─ test_dedupe.py
│  └─ test_integration.py  # pytest-homeassistant-custom-component
├─ tools/anonymize.py      # 실제 덤프 → 익명 픽스처 변환
├─ .github/workflows/      # hassfest, HACS validate, pytest, ruff
├─ hacs.json, README.md(ko/en), LICENSE(MIT), CONTRIBUTING.md
└─ docs/ (PLAN.md, SUPPORTED.md 지원 카드사 표, SETUP.md 컴패니언 앱 설정)
```

### 데이터 모델 (요약)

- `raw_notification` — 원본 보관(기간 설정 가능, 기본 90일 후 삭제): 패키지, 제목, 본문, post_time, 파싱 결과 상태
- `transaction` — 날짜·시각, 유형(지출/수입/이체/취소), 금액, 통화, 가맹점/상대방, 계정, 카테고리, 메모, 원본 ID 목록(중복 병합 이력), 수동 수정 여부
- `account` — 이름, 종류(카드/계좌), 끝자리 매칭 규칙, 가계부 포함 여부
- `category_rule` — 가맹점 키워드 → 카테고리 (예: 우아한형제들/쿠팡이츠 → 식비)

### HA에 노출되는 것

- 센서: 오늘 지출, 이번 달 지출, 이번 달 수입, 마지막 거래, 미인식 알림 수
- 이벤트: `kr_ledger_transaction` (자동화용 — 예: 5만 원 이상 결제 시 TTS)
- 서비스: `kr_ledger.add_transaction`, `update_transaction`, `delete_transaction`, `reparse`, `export_csv`
- 패널: 월간 캘린더(날짜별 합계) → 날짜 클릭 시 거래 목록 → 수정/카테고리 변경, 미인식 큐, 계정·카테고리 설정

## 4. 개발 단계

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **M0 수집 시작** (즉시) | 메인 HA에 임시 자동화: 금융 패키지 알림만 JSONL 파일로 영구 저장. 10일 보존 한계 때문에 오늘 시작해야 데이터가 쌓임 | 파일에 알림이 누적됨 |
| **M1 파서** | 순수 파이썬 파서 + 정규화 + 익명화 픽스처 + pytest. 현재 확인된 8개 포맷 지원 | 현재 수집된 거래성 알림 54건 100% 파싱 |
| **M2 백엔드** | config flow, SQLite 저장, 중복 병합, 이체 판정, 센서·서비스·이벤트 | pytest-homeassistant 통과, 메인 HA에서 실시간 거래 생성 |
| **M3 패널 UI** | 캘린더·일별 목록·수정·미인식 큐·설정 (한/영) | 모바일 컴패니언 앱에서도 사용 가능 |
| **M4 실사용 검증** | 메인 HA에서 2주 운영, 실제 카드 명세서와 대조 | 누락·오인식 0건 목표, 정확도 리포트 |
| **M5 공개** | GitHub 공개 릴리스, HACS 커스텀 저장소 → HACS 기본 목록 등록 신청, 지원 카드사 표, 규칙 제보 이슈 템플릿 | v1.0.0 태그 |

### 메인 HA 테스트 배포 방법

- 개발 중: Samba(`\\<HA IP>\config\custom_components\kr_ledger`)로 바로 복사 → HA 재시작 (이미 Samba 애드온 실행 중)
- 릴리스 검증: GitHub 저장소를 HACS 커스텀 저장소로 추가해서 실제 사용자와 같은 경로로 설치

## 5. 공개 배포를 위한 준비사항

**코드/품질**
- HACS 요구사항: `hacs.json`, `manifest.json`(version, issue_tracker, codeowners), 릴리스 태그, HA brands 등록(아이콘)
- CI: `hassfest`, `hacs/action`, `pytest`, `ruff` — PR마다 실행
- 최소 HA 버전 명시 (개발 기준 2026.11)

**개인정보 (가장 중요)**
- 모든 데이터는 사용자 HA 로컬에만 저장, 외부 전송 없음 (AI 보조는 옵트인)
- 공개 저장소에는 **실제 알림을 절대 커밋하지 않음** — `tools/anonymize.py`로 이름·계좌·카드번호·전화번호·잔액을 가린 픽스처만
- 규칙 제보 기능은 익명화 결과를 사용자에게 미리 보여준 뒤 본인이 직접 제출
- `.gitignore`에 `data/private/` 등 원본 덤프 경로 등록

**사용자 안내 문서**
- 컴패니언 앱 설정: Last notification 센서 활성화 + **허용 목록에 금융 앱/문자 앱만 지정**
- 안드로이드 전용 (iOS 컴패니언 앱은 알림 센서가 없음)
- 지원 카드사/은행 표 + 미지원 시 제보 방법

**커뮤니티**
- 이슈 템플릿: 버그 / 새 카드사 포맷 제보(익명화 체크리스트 포함)
- CONTRIBUTING: 파서 하나 추가하는 방법 (파일 1개 + 픽스처 1개 + 테스트)

## 6. 사용자가 결정·준비할 것

1. **M0 승인** — 메인 HA에 수집용 자동화 + File 알림 엔티티 생성 (금융 패키지만, `/config/kr_ledger_raw/` 저장)
2. **컴패니언 앱 허용 목록** — 폰에서 직접 설정 (지인 문자 수집 중단). 단, 카드사 문자는 문자 앱으로 오므로 문자 앱은 유지 필요 → 통합 쪽에서 발신자 필터로 2차 차단
3. **저장소** — 기본안: `github.com/redchupa/kr_ledger_kit`, 공개, MIT 라이선스
4. **추가 샘플** — 지금 안 보이는 카드사(삼성·BC·NH·우리 등)는 지인/베타테스터 제보로 확보
